Project Overview

This project is a hands-on Platform Engineering laboratory for designing, automating, operating, and validating a highly available Kubernetes platform on Proxmox.

Infrastructure is provisioned with Terraform, system and Kubernetes configuration is automated with Ansible, while Cilium, Helm, Argo CD, Prometheus, Grafana, and NFS provide networking, application delivery, observability, and storage.

Operational Troubleshooting

Problem

Prometheus reported Kubernetes control-plane metrics targets as unavailable.

Investigation

The monitoring path was traced from Prometheus targets through ServiceMonitors and Kubernetes endpoints to the underlying control-plane component configuration.

Prometheus → ServiceMonitor → Endpoint → Kubernetes Component → Listener

Root Cause

The affected metrics endpoint was bound to 127.0.0.1, preventing Prometheus from reaching it through the expected network path.

Resolution

The listener configuration was changed to accept connections through the node network interface. The affected component was restarted and the endpoint was tested directly.

Validation

  • Listener checked with ss
  • Endpoint tested with curl
  • Kubernetes resources verified with kubectl
  • Prometheus targets rechecked

Failure Testing

The platform was tested under controlled failure scenarios to validate behavior beyond the normal healthy state.

Worker Node Failure

A worker node was made unavailable and the resulting cluster behavior and workload recovery were observed.

Control Plane Failure

Control-plane nodes were tested individually to validate the behavior of the highly available Kubernetes control plane.

Troubleshooting

The platform was also used to investigate real operational issues rather than only validating successful deployments.

One monitoring issue involved Kubernetes control-plane metrics being unreachable by Prometheus. The investigation traced the problem from Prometheus targets through ServiceMonitors and endpoints to the component listener configuration.

The root cause was a metrics endpoint bound to 127.0.0.1. The configuration was corrected, connectivity was validated, and Prometheus targets were rechecked.

Ansible Idempotency

Ansible automation was repeatedly executed against the existing environment to verify that the declared state converges without unnecessary changes.

Check mode and repeated execution were used as part of the validation process. Unexpected changes were investigated rather than automatically considered acceptable.
