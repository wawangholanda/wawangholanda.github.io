LOCAL AI PLATFORM

A private, self-hosted AI platform deployed on Debian 13, combining local LLM inference, NVIDIA GPU acceleration, Ansible automation, and Tailscale-restricted HTTPS access.

Debian 13 Ansible Docker NVIDIA Ollama Open WebUI Tailscale

Project Overview

Local AI Platform is a self-hosted AI environment designed to run large language models on privately managed hardware. It combines Ollama as the model inference runtime with Open WebUI as the browser-based interface.

The platform is managed through Ansible, with dedicated roles and playbooks for operating-system preparation, security baselines, GPU configuration, container runtime, AI services, and private HTTPS access.

The engineering focus is on repeatable deployment, controlled network exposure, persistent application data, and operational procedures that can be reviewed and reused.

Architecture

Requests travel through a private network path. Nginx terminates HTTPS on the Tailscale interface and forwards requests to Open WebUI, which communicates with Ollama over a dedicated Docker network.

Authorized Device

Browser connected to the authorized Tailscale network.

Private HTTPS

Nginx reverse proxy with TLS certificates managed through Certbot and Cloudflare DNS-01.

Open WebUI

Browser-based interface published on host loopback, not directly exposed to the LAN.

Private Docker network: ai_backend

Ollama

Local model inference with NVIDIA GPU acceleration and persistent model storage.

Persistent Data

Model weights and Open WebUI application data are stored separately on the host.

Network exposure is deliberately restricted: the Ollama API is not published as a host port, and Nginx listens on the Tailscale interface rather than all network interfaces.

AI Runtime & GPU Acceleration

Ollama

Ollama provides the local inference API and manages downloaded model weights in persistent storage.

Configured image: ollama/ollama:0.40.3

Default model: qwen3.5:2b-q4_K_M

NVIDIA GPU

The host uses an NVIDIA T600 with 4 GiB VRAM. NVIDIA driver configuration and NVIDIA Container Toolkit are managed as dedicated infrastructure phases.

GPU readiness is checked before proceeding with the container runtime and AI services.

Design goal: keep inference local to the managed server while providing a browser-based interface through a private network path.

Infrastructure Automation

Ansible is the source of truth for host configuration, service deployment, and reverse-proxy configuration. The repository separates responsibilities into reusable roles and purpose-specific playbooks.

Baseline & Security

  • Operating-system and package preparation
  • SSH security baseline
  • Docker and NVIDIA runtime configuration
  • Tailscale client management

Application Delivery

  • Ollama and Open WebUI deployment
  • Nginx reverse-proxy configuration
  • HTTPS certificate automation
  • Backup and operational playbooks

Staged Deployment

The quick-start.sh entry point exposes separate phases for preflight checks, Ansible preparation, baseline security, Tailscale, GPU, container runtime, AI services, private proxy configuration, and validation.

Staging allows driver reboots, Tailscale enrollment, service exposure, and other operational prerequisites to be handled explicitly instead of assuming that every deployment can run unattended from start to finish.

Private Access & Security

Network Boundaries

  • HTTPS access restricted to authorized Tailscale clients
  • Nginx bound to the Tailscale interface
  • Open WebUI published only on host loopback
  • Ollama API kept on the internal Docker network
  • Cloudflare DNS-only with DNS-01 certificate validation

Host & Secret Management

  • SSH root login disabled by the security baseline
  • Secrets and environment files kept outside Git
  • Sensitive state and backup archives excluded from version control
  • Container and package versions pinned in configuration
  • Docker group membership treated as privileged access

Private networking is a deliberate security boundary, not a substitute for account security, patch management, careful secret handling, and restricted administrator access.

Persistent Storage & Operations

Application data and model weights are persisted separately so that the AI runtime and user interface can be managed without treating container filesystems as the source of truth.

Component Operational design
Ollama Persistent model storage on the host.
Open WebUI Persistent application data and host-managed Compose configuration.
Backups Dedicated backup workflow for Open WebUI application data.
Model recovery Ollama model weights require a separate backup strategy.
Upgrades Documented backup and upgrade procedure with pinned image versions.

Operational Validation

The repository provides a dedicated validation phase to check the main dependencies and service path after deployment or reconciliation.

  • SSH connectivity and Ansible access
  • Tailscale client and network readiness
  • Docker runtime and NVIDIA GPU readiness
  • HTTPS reachability through the configured private proxy
  • Playbook syntax checks and staged deployment workflow

Deployment phases are designed to be idempotent where supported by their Ansible roles. Driver changes, reboots, service restarts, and application migrations still require explicit operational review.
